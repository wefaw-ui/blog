Every few years I migrate my notes to a new app. Every few years something is lost in translation: formatting mangled, links broken, attachments orphaned somewhere in a proprietary database I can no longer open.

The only notes that have survived every migration intact are the plain text ones. Files I wrote a decade ago open instantly in any editor on any machine. They will open in the next decade too.

## Durability as a feature

We rarely evaluate tools on how long our work will outlive them. We should. The app will change, get acquired, raise its prices, shut down. The words should not have to go with it.

Plain text is not glamorous. It has no sync engine, no collaborative cursors, no clever blocks. What it has is permanence, and permanence turns out to be the feature that matters most once enough years have passed.

> Write for the machine that does not exist yet.

This blog is built from plain text files. Each post is a single `.md` file that looks like this:

```markdown
---
title: A Case for Plain Text
date: 2026-06-04
---
Every few years I migrate my notes to a new app.
```

When the tooling around it changes, and it will, the writing will stay exactly where it is.
